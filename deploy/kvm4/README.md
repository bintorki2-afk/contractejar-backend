# تجهيز سيرفر KVM4 لعقدي (aqdi.sa)

> **حالة هذي الملفات: مكتوبة فقط — ما شُغّلت على أي سيرفر.** كل سكربت يُشغَّل يدوياً وواحد واحد، وبعد ما تتأكد من نتيجة اللي قبله.
> السيرفر: Hostinger KVM4 — Ubuntu 24.04 نظيف — مخصص لعقدي فقط.

## القاعدة الذهبية
**ما نغيّر DNS ولا نحوّل الدومين لين يخلص الفحص كامل** (راجع `docs/seo-baseline/README.md`). السيرفر يُجهَّز ويُجرَّب أول على IP السيرفر نفسه (أو دومين مؤقت) والموقع القديم على Topline يبقى شغال.

## الترتيب

| # | السكربت | وش يسوي | يحتاج DNS؟ |
|---|---------|---------|------------|
| 1 | `01-base.sh` | تحديثات، مستخدم `deploy`، جدار ناري، fail2ban، swap، توقيت الرياض | لا |
| 2 | `02-stack.sh` | nginx + PHP 8.3 + MySQL 8 + Composer + Node 20 | لا |
| 3 | `03-database.sh` | قاعدة `aqdi` ومستخدمها بكلمة سر عشوائية (تنحفظ في ملف للجذر فقط) | لا |
| 4 | `04-app.sh` | سحب الخلفية، composer، `.env` من القالب، الصلاحيات، خدمة المجدول | لا |
| 5 | `05-nginx.sh` | موقع nginx للخلفية + ملف التحويلات 301 | لا |
| 6 | `06-backup.sh` | نسخ احتياطي يومي للقاعدة والملفات (يحتفظ بآخر 7) | لا |
| 7 | `07-ssl.sh` | شهادة Let's Encrypt | **نعم** — بعد ما الدومين يشاور على السيرفر فقط |

## قبل البدء
1. مفتاح SSH للدخول على السيرفر (ما نستخدم كلمة سر الجذر).
2. مفتاح نشر (deploy key) للقراءة فقط على ريبو `contractejar-backend` في GitHub.
3. قيم `.env` الحقيقية (Moyasar، Firebase، Telegram، تقنيات) — **تُكتب على السيرفر فقط ولا ترفع للريبو**.

## تشغيل سكربت
```bash
sudo bash 01-base.sh
```
كل سكربت: يوقف عند أي خطأ، وتقدر تعيد تشغيله بدون ضرر (idempotent)، ويطبع وش سوّى.

## بعد التجهيز (قبل أي تحويل)
```bash
curl -I http://IP_السيرفر/api/v2/health
```
ونقارن استجابة الـ API بين السيرفر الجديد والقديم، ونستورد البيانات (بند 4) على نسخة تجريبية أول.

## ملاحظات
- المجدول (`schedule:work`) يشتغل كخدمة systemd. نفس سلوك Railway.
- ملف الرفع (`storage/app/public`) على القرص مباشرة، وفي النسخ الاحتياطي اليومي.
- مدونة/روابط `aqdi.sa/blog/...`: ما نكتب لها قواعد فعلية قبل قرار الهيكل النهائي. القالب في `nginx/aqdi-redirects.conf.example`.
