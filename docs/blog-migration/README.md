# نقل مدونة عقدي القديمة — بند 6

> الهدف: كل مقال ينتقل **بنفس الرابط حرفياً**، وكل رابط كان يجيب ترافيك يبقى يرجع 200 أو 301 مباشر.
> **ما يُشغَّل على الإنتاج إلا بعد ما تقول «نفّذها».**

## الأدوات

| الأمر | وش يسوي | يكتب؟ |
|---|---|---|
| `blog:import-legacy` | ينقل جدول `blogs` القديم + يطلع خريطة 301 + ملف nginx | **لا**، إلا مع `--commit` |
| `seo:verify-urls` | يفحص روابط خط الأساس (200 أو 301 بقفزة وحدة) | لا (قراءة فقط) |

## الخطوات

### 1. تحميل التصدير في قاعدة مؤقتة
```bash
mysql --default-character-set=utf8mb4 aqdisa_legacy < aqdisa_123.sql
```
وفي `.env`:
```
LEGACY_DB_DATABASE=aqdisa_legacy
LEGACY_DB_USERNAME=...
LEGACY_DB_PASSWORD=...
```
(أو بدل القاعدة: ملف تصدير phpMyAdmin للجدول بصيغة JSON أو CSV مع «أسماء الأعمدة في أول سطر» عبر `--file=`.)

### 2. تجربة (ما يكتب شي)
```bash
php artisan blog:import-legacy --connection=legacy --images-dir=/path/old/storage/app/public
```

### 3. مراجعة التقارير
في `storage/app/blog-import/<الوقت>_dryrun/`:

| الملف | المحتوى |
|---|---|
| `import-report.csv` | كل مقال: create / skip / error + السبب + تحذيرات (صورة ناقصة، Meta فاضي…) |
| `redirect-map.csv` | كل رابط مدونة في قوقل: same / redirect / suggest / unmatched + النقرات |
| `redirects.nginx.conf` | تحويلات 301 التلقائية (النسخ المشوّهة فقط) |
| `summary.json` | الأرقام |

**شرط المتابعة:** `error = 0`، وكل تصادم تشكيل (`skip_collation_collision`) وكل `suggest`/`unmatched` اللي لها نقرات (`critical = yes`) لها قرار منك.

### 4. الحفظ الفعلي
```bash
php artisan blog:import-legacy --connection=legacy --commit
```
أي خطأ في أي صف ⇒ **ما ينحفظ شي أبداً** (معاملة وحدة). قبل الحفظ يقرأ كل صف ويقارنه بالأصل بايت ببايت (الرابط، العنوان، المحتوى، الصورة، الـ Meta، الحالة، الظهور، التواريخ).

### 5. التحويلات
```bash
sudo cp redirects.nginx.conf /etc/nginx/aqdi/redirects.conf && sudo nginx -t && sudo systemctl reload nginx
```

### 6. الفحص
قبل DNS (على السيرفر الجديد):
```bash
php artisan seo:verify-urls --ip=IP_السيرفر --map=storage/app/blog-import/<الوقت>_commit/redirect-map.csv
```
بعد DNS:
```bash
php artisan seo:verify-urls
```
> `--ip` يوجّه الدومين للسيرفر الجديد بنفس الرابط والـ https (مثل `curl --resolve`)، فيشتغل قبل وبعد SSL. و`--map` يتأكد إن كل 301 يروح **للمقال الصحيح**، مو أي صفحة ترجع 200.

## الحماية المضمّنة

| الحماية | التفصيل |
|---|---|
| تجربة افتراضية | بدون `--commit` ما يتغير شي (كل شي داخل معاملة تُلغى) |
| الرابط حرفي | لا trim ولا تحويل؛ مقارنة بايت ببايت بعد الحفظ |
| ترميز خاطئ | «ØªØ¹…» في الرابط أو العنوان = خطأ يمنع الحفظ |
| مقال موجود | ما ينكتب فوقه إلا بـ `--on-conflict=update` |
| مكرر في المصدر | الأول ينتقل، الثاني يتبلّغ عنه |
| رابط يختلف بالتشكيل فقط | MySQL يعتبره نفس الرابط ⇒ **يمنع الحفظ** لين تقرر، ثم `--accept-collisions` (يبقى الأول، والثاني يتبلّغ عنه) |
| رابط فاضي | يتولد بنفس خوارزمية الموقع القديم |
| Location في 301 | دايماً مرمّز (ASCII)، مو عربي خام |
| الاقتراحات | تشابه إملائي (≥85%) يحتاج موافقتك، ما يدخل nginx تلقائياً |
